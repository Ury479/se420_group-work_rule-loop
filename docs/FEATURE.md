## 一、产品定义

### 1.1 一句话定位

RuleLoop 是一个最小化的个人经验转化引擎：帮助用户把重复发生或影响较高的错误转化为下次可执行的规则，并用后续行为验证规则是否有效。

### 1.2 要解决的问题

用户并不缺记录工具，真正缺少的是三件事：

1. 判断一件事是否值得长期处理；
2. 把反思压缩成下一次能执行的动作；
3. 在类似场景再次出现时，知道自己是否真的改变。

因此 RuleLoop 的产出不是“更多记录”，而是“更少重复错误”。

### 1.3 核心用户

P0 只服务产品所有者本人，所有交互按真实个人使用习惯校准：

- 手机为主，电脑为辅；
- 事件发生后快速记录，晚些时候完成复盘；
- 不希望维护复杂标签、项目或知识库；
- 愿意主动反思，但不愿填写冗长表单；
- 更关心“这次有没有做得不同”，而不是连续签到或使用时长。

### 1.4 非目标

RuleLoop 不是：

- 待办、日程或 GTD 系统；
- 通用笔记或知识库；
- 情绪诊断或心理治疗产品；
- 社交、排行榜或公开分享平台；
- 自动替用户完成反思的 AI 助手；
- 复杂数据分析 Dashboard。

## 二、第一性原理

### 2.1 产品目标函数

```text
产品价值 = 同类错误减少程度 × 规则在关键时刻的可执行性
```

记录量、页面停留时间和规则总数都不是目标。规则越多不一定越好；没有被触发或无法执行的规则是噪音。

### 2.2 三条产品原则

1. **先判断价值，再增加规则**：普通事件只存档，避免规则膨胀。
2. **规则必须描述动作**：每条规则至少包含触发场景、风险信号和最小行动。
3. **没有验证就没有闭环**：规则只有经过真实场景验证，才成为成长证据。

### 2.3 规则准入门槛

当事件满足以下任一条件时，进入规则流程：

- 用户标记为“重复发生”；
- 事件影响等级为“高”。

其余事件默认只存档，可查看、编辑或稍后补充，但不会自动生成规则。

```text
qualifiesForRule = isRepeated || impactLevel === "high"
```

当事件已命中某条已有规则时，优先关联已有规则并增加验证记录，避免创建同义规则。

## 三、核心闭环与状态

### 3.1 主流程

```text
记录事件
  ↓
判断：是否重复发生或高影响？
  ├─ 否 → 存档 → 可稍后查看
  └─ 是 → 加入待复盘
            ↓
          完成复盘
            ↓
      关联已有规则 / 创建新规则
            ↓
        规则启用并等待触发
            ↓
      记录一次真实场景验证
            ↓
      形成有效、无效或待观察证据
```

### 3.2 事件状态

| 状态 | 含义 | 允许动作 |
|---|---|---|
| `archived` | 普通事件，已直接存档 | 查看、编辑、删除、升级为待复盘 |
| `pending_review` | 值得处理但尚未复盘 | 开始复盘、编辑、删除 |
| `reviewed` | 已完成复盘但未形成新规则 | 查看复盘、关联已有规则 |
| `rule_linked` | 已关联已有或新建规则 | 查看规则、添加验证 |

### 3.3 规则状态

| 状态 | 含义 |
|---|---|
| `draft` | 已生成但尚未确认 |
| `active` | 正在使用，等待真实场景验证 |
| `paused` | 暂停提醒与统计，保留历史 |
| `archived` | 不再使用，仅作为历史证据 |

### 3.4 规则有效性

- 少于 3 次验证：`待观察`
- 至少 3 次验证且结果改善率 ≥ 60%：`有效`
- 至少 3 次验证且结果改善率 < 60%：`需要调整`

该判断只提供反馈，不替用户做价值判断。

## 四、信息架构与页面数量

### 4.1 页面总数

P0 固定为 **8 个路由页面**。页面数量按可独立访问、承担独立用户任务的路由计算，不把弹窗、筛选状态和编辑模式重复计为页面。

| # | 页面 | 路由 | 页面唯一任务 | 底部导航 |
|---:|---|---|---|:---:|
| 1 | 首页 | `/` | 告诉用户当前最值得完成的下一步 | ✅ |
| 2 | 快速记录 | `/record` | 在 60 秒内记录事实并完成价值判断 | ❌ |
| 3 | 事件详情 | `/events/[id]` | 查看事件及其从复盘到规则的完整轨迹 | ✅ |
| 4 | 待复盘 | `/reviews` | 找到并处理尚未完成的高价值事件 | ✅ |
| 5 | 复盘工作台 | `/events/[id]/review` | 将事件转化为动作或关联已有规则 | ❌ |
| 6 | 规则库 | `/rules` | 查找和管理现有规则 | ✅ |
| 7 | 规则详情 | `/rules/[id]` | 编辑规则并记录真实场景验证 | ✅ |
| 8 | 成长档案 | `/archive` | 查看可追溯的行为改变证据 | ✅ |

### 4.2 主导航

移动端底部导航由四个目的地和一个主操作组成：

```text
首页    待复盘    ＋记录    规则    档案
```

记录和复盘工作台是专注流程，只显示返回、进度和保存状态，不显示底部导航。

### 4.3 不新增的页面

- 不单独设置“档案详情”：档案条目直接链接事件或规则详情。
- 不单独设置“复盘详情”：完成后的复盘工作台切换为只读模式。
- 不单独设置“编辑事件/编辑规则”页面：详情页内切换编辑状态。
- 首次引导使用首页空状态完成，不建立多步 onboarding 页面。

## 五、页面需求

### 5.1 首页 `/`

**单一任务：** 让用户在 5 秒内知道下一步该做什么。

#### 内容优先级

1. 下一步行动：继续复盘、验证规则或记录事件，只突出一项；
2. 待处理摘要：待复盘数量、待观察规则数量；
3. 最近轨迹：最近 3 条事件及其状态；
4. 结果摘要：重复事件、有效规则和改善次数。

#### 关键交互

- 主按钮根据当前状态显示“继续复盘”“记录一次验证”或“记录刚发生的事”；
- 点击事件进入事件详情；
- 点击规则进入规则详情；
- 空状态使用一个完整示例解释闭环，不使用四宫格功能介绍。

#### 验收标准

- 首屏只存在一个最高视觉权重的行动按钮；
- 最近轨迹最多 3 条，其他内容进入对应列表；
- 用户无需理解系统术语就能决定下一步。

### 5.2 快速记录 `/record`

**单一任务：** 记录事实并判断事件是否值得进入复盘。

#### 必填字段

| 字段 | 控件 | 说明 |
|---|---|---|
| 发生了什么 | 单行扩展文本框 | 5–80 字，只描述事实 |
| 场景 | 单选 | 学习/工作、时间、消费、人际、健康、其他 |
| 影响等级 | 单选 | 低、中、高；解释实际影响而非情绪强度 |
| 是否重复发生 | 单选 | 第一次 / 曾经发生过 |

#### 可选字段

- 实际后果；
- 当时的身心状态；
- 发生时间，默认当前时间。

#### 提交结果

- 普通事件：显示“已存档，这次不创建规则”，返回事件详情；
- 重复或高影响事件：显示准入原因并进入复盘工作台；
- 若场景可能匹配已有规则，在复盘工作台中优先展示关联建议。

#### 验收标准

- 正常输入不超过 60 秒；
- 普通事件不会生成规则草稿；
- 价值判断理由对用户可见，不是黑盒。

### 5.3 事件详情 `/events/[id]`

**单一任务：** 回答“这件事后来如何被处理”。

#### 详情页功能

- 展示事实、场景、影响、是否重复、后果、身心状态和时间；
- 展示轨迹：已记录 → 已复盘 → 已关联规则 → 已验证；
- 普通事件可“升级为待复盘”；
- 高价值事件可“开始/继续复盘”；
- 查看完成后的复盘内容；
- 打开关联规则；
- 编辑事件；
- 删除事件，删除前说明对复盘和验证记录的影响。

#### 验收标准

- 所有后续对象均可从来源事件追溯；
- 页面只保留一个主行动，其余操作进入次级菜单；
- 删除属于显式确认操作。

### 5.4 待复盘 `/reviews`

**单一任务：** 找到最值得继续处理的事件。

#### 内容

- 默认显示待复盘事件，按“高影响优先，其次时间倒序”排列；
- 每项显示事件、准入原因、发生时间和复盘进度；
- 次级筛选为“待复盘 / 已完成”；
- 已完成项进入只读复盘工作台。

#### 验收标准

- 列表为空时引导记录事件，不制造待办焦虑；
- 不提供复杂排序、标签或批量操作。

### 5.5 复盘工作台 `/events/[id]/review`

**单一任务：** 把高价值事件转化为下一次能执行的动作。

#### 三个核心问题

1. 最早出现的风险信号是什么？
2. 哪个决策点本可以做出不同选择，为什么没有做到？
3. 下次在同一信号出现时，最小可执行动作是什么？

根因类型“知识、执行、情绪、环境”作为辅助分类，不替代文字回答。

#### 规则处理

- 优先展示可能匹配的已有规则；
- 用户可关联已有规则，避免生成重复规则；
- 无匹配时生成规则草稿；
- 规则草稿使用“当……且看到……时，先……”句式；
- 支持保存草稿和继续填写；
- 普通事件即使后来复盘，也只形成教训，不自动创建规则，除非先更新为重复或高影响。

#### 验收标准

- 完整复盘与确认规则草稿合计不超过 3 分钟；
- “最小行动”为空时不能完成；
- 刷新或意外返回不会丢失已输入草稿；
- 完成后跳转关联规则详情，而不是规则列表。

### 5.6 规则库 `/rules`

**单一任务：** 快速找到当前需要使用或调整的规则。

#### 内容与筛选

- 默认展示启用规则；
- 状态筛选：启用、草稿、暂停、归档；
- 场景筛选保持单选，不引入自由标签；
- 每张卡片只显示触发场景、风险信号、最小行动、状态和验证结论；
- 重复或高度相似规则给出合并提示，不自动合并。

### 5.7 规则详情 `/rules/[id]`

**单一任务：** 在真实场景中使用、验证并调整一条规则。

#### 详情页功能

- 查看和编辑标题、触发场景、风险信号、禁止动作、推荐动作、最小行动；
- 启用、暂停或归档规则；
- 查看来源事件和来源复盘；
- 添加一次验证；
- 查看验证时间线；
- 显示触发次数、想起次数、遵守次数和结果改善次数；
- 根据至少 3 次验证显示“待观察、有效、需要调整”；
- 支持复制规则文本；
- 不允许直接永久删除已有验证历史的规则，只能归档。

#### 添加验证

每次验证只回答：

1. 这次是否想起规则？
2. 是否按规则行动？
3. 结果是否比过去更好？
4. 可选备注。

提交目标时长不超过 30 秒。

### 5.8 成长档案 `/archive`

**单一任务：** 用事实回答“我是否真的在改变”。

#### 内容

- 由事件、复盘、规则和验证实时计算，不建立独立档案数据源；
- 时间线展示普通存档、高价值复盘、规则创建和验证结果；
- 顶部只展示三项结果：本周期重复事件数、有效规则数、改善次数；
- 条目可跳转事件或规则详情；
- 里程碑只基于真实数据，不使用无依据的连续天数。

## 六、核心业务规则

### BR-01 事件分类

```text
普通事件 = 非重复 且 影响不是高
高价值事件 = 重复发生 或 影响为高
```

### BR-02 规则准入

- 普通事件提交后状态为 `archived`；
- 高价值事件提交后状态为 `pending_review`；
- 后端必须重新计算准入结果，不能只相信客户端状态。

### BR-03 避免重复规则

- 复盘完成前按场景和风险信号查询启用/暂停规则；
- 命中已有规则时默认建议关联；
- 用户明确确认后才创建新规则。

### BR-04 验证统计

```text
触发次数 = validation 总数
想起率 = 想起次数 / 触发次数
遵守率 = 遵守次数 / 触发次数
改善率 = 结果改善次数 / 遵守次数
```

分母为 0 时显示“暂无数据”，不显示 0%。

### BR-05 删除与归档

- 无下游关联的事件可以永久删除；
- 已有关联复盘或验证的事件删除前必须明确说明级联影响；
- 已有验证历史的规则只能归档；
- P0 提供全部数据 JSON 导出与本地数据库备份说明。

## 九、核心指标

| 指标 | 定义 | P0 目标 |
|---|---|---:|
| 记录完成时间 | 打开记录页到保存成功 | < 60 秒 |
| 高价值事件复盘完成率 | 完成复盘数 / 高价值事件数 | ≥ 70% |
| 规则验证覆盖率 | 有至少一次验证的启用规则 / 启用规则 | ≥ 60% |
| 规则想起率 | 想起次数 / 触发次数 | 先建立基线 |
| 规则遵守率 | 遵守次数 / 触发次数 | 先建立基线 |
| 行为改善率 | 改善次数 / 遵守次数 | 先建立基线 |
| 同类错误重复数 | 同一场景与信号的再次事件数 | 逐周期下降 |

不再把“教训转规则率 >80%”作为目标，因为它会激励创建不必要的规则。

## 十、验收场景

### 场景 A：普通事件直接存档

用户记录一次低影响、首次发生的失误。保存后系统明确提示“这次只存档，不创建规则”，事件详情可查看和编辑，规则库不增加新条目。

### 场景 B：重复事件关联已有规则

用户记录“又一次在疲惫时刷视频超时”，选择“曾经发生过”。系统将其加入待复盘，并在工作台推荐已有规则。用户关联规则并提交一次验证，不创建重复规则。

### 场景 C：高影响事件创建新规则

用户记录一次首次发生但影响较高的文件误提交。复盘完成后没有匹配规则，系统生成草稿：“当准备提交重要文件且感到赶时间时，先重新打开附件确认内容与版本。”用户确认后启用。

### 场景 D：验证规则有效性

规则累计三次触发，其中三次想起、两次遵守、两次改善。详情页显示触发 3、想起 3、遵守 2、改善 2，改善率为 100%，结论为“有效”。

## 十一、文案与体验原则

- 使用用户能控制的动作词：“保存事件”“开始复盘”“启用规则”“记录验证”。
- 不使用责备式文案，不把错误包装成打卡游戏。
- 普通事件存档是正常结果，不显示失败或遗憾状态。
- 空状态给出下一步，不使用泛化鼓励语。
- 一个页面只有一个最高权重按钮；危险操作保持低视觉权重并二次确认。
