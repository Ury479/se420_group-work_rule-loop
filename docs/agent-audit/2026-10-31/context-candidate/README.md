# 原架构 Agent 上下文候选

状态：待评审、未采用的后端补丁。没有写入生产 `src/`，没有新页面、认证体系、业务表、Hermes 进程或模型请求。它用于补齐已在真实链路核验中发现的来源读取缺口，不是新的独立产品。

## 复用与新增

候选增加三个内部服务模块，复用原工程的 `withAccount`、`getUserId`、账户事务／RLS、`getEventCase`、`getRules`、`selectMatchingRules` 及既有表定义。不改变这些原方法的返回值，不新建 Agent 档案表或行动事实表，也不写规则计数。

- `src/lib/agent/event-context-repository.ts`：在当前登录账户的短事务中读取当前事件、最多 5 个既有同场景案例、对应复盘／案例候选规则、相关和明确关联的主规则、经验原始来源、版本及近期反馈。
- `src/lib/agent/event-context.ts`：把既有对象投影为带类型与来源关联的上下文，生成内容快照、请求指纹和模型侧引用；提供引用片段校验和新旧上下文比较。
- `src/lib/agent/event-analysis.ts`：生成 Hermes 请求体，约束分析返回值，校验重复模式、经验适用性和来源，并按运行身份、上下文与终态协调候选结果。

三个文件将来的落位是原工程同名路径，不是额外服务器。当前没有可供浏览器调用的新 API，也没有生产 Server Action 接线。调用入口必须继续通过原账号会话；内部上下文及绑定信息不能直接当作客户端提交体。

## 已实现的候选行为

1. 事件里的 `event_candidate_rule` 和全局 `confirmation_rule` 使用不同类型，即使数字 ID 相同也不会混淆。
2. 沿原始 `event_review`、`ash_memo`、`mistake_review`、`mind_review` 关系读取经验，不把导出的摘要当作全部事实。只有允许字段进入模型上下文；账号 ID、数据库裸 ID 与绑定映射留在服务端。
3. 主规则的当前版本独立标识；近期实际反馈保留其当时的版本引用。旧版本的成功或失败仍可用于复盘，但不能算成新版规则已经有效。会话级反馈也不被解释为其中每条规则都有效。
4. 暂停／归档规则、撤回的经验和依赖它们的内容不进入模型正文；来源缺失、版本缺失／歧义、历史数据损坏或抽样窗口不完整时有明确限制标记。
5. 找到相关规则只代表候选召回。所有候选的当前适用性仍是 `unassessed`；来源齐全、版本一致和触发条件非空，只允许进一步评估，不构成用户确认或执行授权。
6. 内容哈希不依赖所有表都有 `updatedAt`。源文、状态、版本、来源关系或语言请求变化会使旧请求失效；顺序变化不制造无意义失效。
7. 引用校验要求引用本次已有来源的具体字段与原文片段。它能拦截伪造引用，不能证明整段分析语义正确或教训一定适用。
8. 允许当前没有可靠历史规则的情况，仍可返回当前事件供分析，不强迫建立一条“已确认教训”。保留中／英／泰语言标记和原文，不宣称已经验证三语生成质量。

## 分析协议与提示词

[实际生成的英文提示词](instructions.example.txt) · [合成上下文](context.example.json) · [完整请求体示例](prepared-request.example.json)

请求体只有 `instructions` 和已筛选的 `input`；示例未发送给模型。沿用旧接入候选的证据约束、候选结果及未知终态处理原则，移除了其“必须有已确认学习经验／材料”等限制，以适配原 RuleLoop。

返回结构区分观察、自述与假设；重复模式必须引用至少两次不同经历，不能把同一事件及其复盘算成两次。经验评估要保留原触发条件，引用规则、来源及已提供版本；仅同领域的标签不足以支持“可能适用”。没有已记录的排除条件时明确标注未记录，模型只能提出待审阅的排除设想。

下一步只是一张 `action` 卡片草稿，允许不依赖任何历史规则、仅帮助处理当前事件。返回体不接受工具操作、完成状态或规则生效指令；运行失败／取消／中断不能因为有文字输出而通过，停止中、未知和未来状态继续保留为待核对。所有通过的结果仍是 `ready_for_user_review`，行动未开始、规则效果未推定，费用未知。

来源精确引用和协议检查不能证明分析语义正确、三语生成自然、模型抵抗资料内指令或建议对用户有效。真实 Hermes 的工具权限必须在运行时配置及验收，提示词中的禁止事项不是权限隔离机制。上述模型质量与运行边界需要后续真实测试，未被本轮模拟返回值代替。

独立配置不加载项目 `.env.test` 或根测试初始化。每次联测新建自己的临时 PostgreSQL 簇，只监听私有 Unix socket，结束后停止并清理；没有重启或连接原有数据库。候选同时通过 TypeScript 检查。没有运行原项目的全量测试或生产构建，因为补丁未应用；这些结果不能代替最终接入后的验收。

## 具体限制

- 检索复用当前同场景／规则召回逻辑，尚不是跨全部模块的语义搜索，也不等于梳理了完整个人档案。
- 历史窗口是该账户最近 30 条已验证会话；同一会话涉及未纳入当前上下文的规则时保留范围限制。缺失或损坏的版本快照不伪造补齐。需要更远历史时，应明确扩展读取范围。
- 上下文最多 200 个来源，模型正文最多 96,000 字节；超限明确失败，不静默截断引用或原文。这是传输保护，不是模型 token、费用或余额管理。生产接线需要提供缩小范围与原有人工操作的反馈。
- 未执行真实 AI 推断、业务写入、用户采纳、持久运行、Hermes 会话／记忆清理、提醒或计费。来源比较与结果协调需要在真实返回及采纳入口重新读取并调用，不能仅凭存在这些函数就声称防过期已上线。
- `0002_agent_rule_sources.sql` 是读取 `linked_rule_id` 的已有依赖。本次只在临时数据库应用，线上迁移状态仍未以此证明。
- 原事件卡片的 `event_case/event` 问题仍由上一级的独立最小补丁解决，本候选不掩盖或绕过它。
