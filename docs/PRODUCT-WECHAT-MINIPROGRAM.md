# RuleLoop 微信小程序 · 产品方案

> v0.1 · 2026-11-11 · **待人工核对，尚未开发**  
> 配套：[需求规格与本机项目核对](PRD-WECHAT-MINIPROGRAM.md) · [RuleLoop 产品定义](../CONTEXT.md)

## 1. 微信入口解决什么

让已经在使用 RuleLoop 的个人开发者，从微信打开同一个账号，在手机上接着做手头的事。典型时刻是准备付一笔工具费用，想先看看这笔钱相当于什么；或隔几天回到项目，想快速找到上次做到哪里、下一步做什么。

例如，用户在电脑上保存「下次先在手机上测表单」。在微信打开「继续上次」就能读到这句话，测完后留下一条实际产出；回到电脑时，能继续查看同一条进展。这个入口沿用 RuleLoop 的投入回看方向。独立的「投入 → 产出 → 取舍 → 真实使用验证」工作台仍是后续产品议题，首期复用已有能力。

## 2. 首期体验

首期建议供本人和指定体验成员使用。首次在微信内使用现有 RuleLoop 邮箱账号登录；在会话有效时，再打开直接进入现有首页。微信内与浏览器的会话分别建立，登录同一实例上的同一账号即可看到同一份业务数据。

保留账号版已有的移动导航和页面顺序。小程序提供入口、加载和失败恢复，网页继续负责页面内的导航。旧小程序有五个原生标签，首期建议用一个网页容器承载当前账号版，以免用户面对两套底栏。

| 使用时刻 | 用户从哪里进入 | 做完后能看到什么 |
| --- | --- | --- |
| 打开后想知道近期要做什么 | 首页 → 未来一周／工作台 | 看到任务及日期，打开原任务；已存在的消费记录从原入口继续处理 |
| 隔几天继续做项目或读论文 | 首页 → 继续上次 | 找到已保存的下一步或最近进展，新增打卡后能在两端看到同一记录 |
| 付款前想比较机会成本 | 底栏「换算」→ 结果／历史 | 看见当前换算与当时的价格快照，启动冷静期后能回来处理原记录 |
| 想按规则审核一笔支出 | 「复盘」进入决策拦截台 | 查看原记录的冷静期、审核状态和建议，由本人保存最终决定 |

首页、工作台、继续上次、金额换算、决策拦截和账号流程是首批逐项验收对象。现有站内其他入口随网页保留，先验证基本可达。微信快捷登录、订阅提醒、支付、公开分享、全量原生重做和新的投入回看工作台不在首期。

## 3. 封装路线

| 方案 | 用户得到什么 | 需要满足什么 |
| --- | --- | --- |
| **A · 网页封装（首选，待确认资格）** | 在微信内使用现有账号版，保留表单、记录、规则与移动导航；首期用现有邮箱账号登录 | 正式小程序主体能使用 `web-view`，候选 HTTPS 域名能通过业务域名校验，iOS 与 Android 上登录、返回和保存可用 |
| **B · 原生核心流程（备选，另行确认）** | 首页、打卡或换算等选定流程用原生页面；仍以同一 RuleLoop 账号数据为目标 | 重新选择首期闭环，设计原生界面，补齐面向小程序的鉴权和业务接口；现有网页的 Server Actions 不能直接当作小程序接口 |

微信的 [`web-view` 官方文档](https://developers.weixin.qq.com/miniprogram/dev/component/web-view.html) 明确个人类型暂不支持该组件，承载 RuleLoop 网页需要配置业务域名。本机的旧封装只能说明此前做过这条路线。如果拟用主体无权使用 `web-view`，或域名无法通过校验，暂停方案 A，再核对方案 B 的范围和成本。

## 4. 怎样判断首版有用

- **能接上。** 在一次实际开发或论文阅读中，从微信找到上次进展并留下一条新进展；回到电脑打开同一条记录。
- **能继续决策。** 用一笔实际考虑过的支出做换算，退出微信后重开，继续处理原记录；如需审核，在同一支出记录中保存最终决定。
- **能解释失败。** 会话失效时能重新登录回到原页面；断网或网页不可用时有清楚的恢复动作，用户能分辨是否已经保存。

体验期建议先用一周，记录「在哪一步回到浏览器、原因是什么」，再决定是否值得做原生交互。逐项通过的条件见[需求规格](PRD-WECHAT-MINIPROGRAM.md)。
