# RuleLoop 首页与事件 AI · 设计交接稿

2026-11-07 · 给设计 AI 的可执行任务。请基于现有 RuleLoop 账户应用，为首页 `/` 和事件详情 `/event-library/[id]` 制作可点击的 Web 高保真，交付桌面和移动版本。界面打开后，用户应能立即说出三件事：**现在关注什么、AI 能帮我做什么、下一步点哪里。**

## 设计范围

现有业务顺序是 **事件／关键确认 → 复盘与判断 → 规则 → 下一次行动 → 结果验证 → 成长档案**。保留现有导航去向和人工操作，调整两页的信息层级、界面样式和 AI 入口的位置。首页负责指向当前事项和事件入口，AI 在单条事件中工作。任务与决策继续分开保存并在项目中关联。若使用网站交付案例，制作自测通过和客户验收应分别显示，前者可由用户确认且附件可选。

| 页面 | 现有能力 | 本次设计提案 |
| --- | --- | --- |
| 首页 | 主线取自活跃的关键确认，主按钮经 `/critical-confirmations/[id]` 进入现有检查流程。没有活跃项时进入现有记录入口 `/arm`。下方还有行为闭环、统计、消费换算和最近轨迹。 | 把事项、状态和下一步集中到首屏。提供一个解释 AI 用途的轻量入口，去现有事件库。 |
| 事件详情 | 有事件状态、复盘表单或记录、已有规则、卡片和同场景案例。已有复盘时出现「用 GPT 分析」与「加入 Daily Review」；前者输出可复制的上下文。 | 让 AI 入口靠近当前事件。点击后在同页显示有依据的经验、适用条件和一条可编辑建议。保留上下文导出及 Daily Review，并延用原事件卡片记录实际行动和结果。真实 AI 功能属于拟议状态。 |

## 视觉方向

借鉴 Apple HIG 的三个做法。将最重要的信息放在阅读起点，让相关内容对齐成组，用明显的样式突出当前主动作。借鉴 `guizang-ppt-skill` 的网格、字号层级、强调色和溢出检查方法，按响应式 Web 工作台组织内容。两页使用同一套控件和状态样式，保留 RuleLoop 标志。 [Apple 设计原则](https://developer.apple.com/design/human-interface-guidelines/design-principles) · [Apple 布局](https://developer.apple.com/design/human-interface-guidelines/layout?changes=lat_3__1_2) · [Apple 按钮](https://developer.apple.com/design/human-interface-guidelines/buttons) · [归藏网格与排版](https://github.com/op7418/guizang-ppt-skill/blob/main/references/layouts-swiss.md)

| 项目 | 可直接用于第一稿的建议 |
| --- | --- |
| 色彩与质感 | **浅色作为首稿提案。** 背景 `#F5F5F7`，表面 `#FFFFFF`，主文字 `#1D1D1F`，辅助文字 `#5E626C`，主动作蓝 `#005CC5`。风险用琥珀色配「待确认」等文字，确认或完成用绿色配明确状态名。列表用细分隔线，重点区域可用一层浅底和轻描边。 |

## 首页

从上到下按以下顺序组织。桌面可以并排摆放重点事项和辅助说明，移动端按相同阅读顺序堆叠。

1. **现在关注**。只突出一条现有活跃关键确认。显示具体事项名、一条真实状态和一个指向现有检查流程的主按钮。常规文案「查看当前确认」。比如「确认预约表单的交付条件」处于「检查中」时，主按钮可直接写「继续检查」。如果确有需要核对的已记录事实，可用一行补充。缺少依据时使用原有状态。
2. **AI 能帮你**。在主事项下方或旁边放一个轻量区域，文案「在事件详情里，找回相似经验并整理一个下一步」。次级入口「去事件库」链接至 `/event-library`，用户从库中选事件。以能力说明呈现，首页的确认进度继续由原关键确认数据提供。设计时把拟议的站内 AI 能力标为「原型演示」。
3. **最近轨迹与现有入口**。用一行一个事项的列表展示标题、可核实的状态和日期。行为闭环及指标移到主事项之后，以紧凑区块保留。保留规则、档案和换算的原有去向。导航若展示通往 `/spending-review` 的现有「复盘」，建议明确写「消费复盘」，以便区分事件内的复盘。
4. **首页空态**。把第 1 区替换为「还没有待确认的事项」，主按钮为「记录一件事」，沿用 `/arm`。AI 说明可继续指向事件库。状态和统计只使用已有数据。

## 事件详情

1. **先让用户认出事件**。保留「返回事件库」、标题、当前状态和主要事件事实。状态管理保持可达，删除沿用原有确认步骤。复盘原文继续在原页面可读，移动端的长记录可展开。
2. **把 AI 放进当前事件**。在标题和状态之后放「AI 帮你找回相似经验」区，说明「根据这条事件和已有复盘，找出可参考的过往记录，给你一个可以开始的动作」。已有复盘时显示主按钮「分析这条事件」。未复盘时沿用原表单，AI 区显示「完成复盘后可分析」及「去复盘」。该入口在同页展开。
3. **结果只需三块**。先显示「需要关注什么」，把原记录与 AI 推断标清。再显示「为什么」，提供来源名称、日期、可打开的片段与适用条件。最后显示「下一步」，给一个有具体产出的动作，主按钮「编辑行动草稿」，次级选项「这次不适用」。完整来源可按需展开。
4. **采纳回到原卡片**。编辑时显示目标位置「本事件 › 行动卡」。用户点击「保存到行动卡」后，展示已保存位置和「查看行动卡」。保存表示行动已记录，后续执行结果仍用既有卡片、复盘或验证入口记录。规则和验证状态由原流程更新。把「复制分析上下文」和「加入 Daily Review」放在 AI 区的次级操作中，沿用已有能力和显示条件。

### 关键状态

| 状态 | 用户应看到并可以做什么 |
| --- | --- |
| 无复盘 | 显示当前进度及现有复盘入口。AI 分析随已有复盘开启。 |
| 正在分析 | 在同一位置提示正在查找相关记录，保留事件内容，提供取消。 |
| 有建议 | 一句需要关注的事、一条可展开的依据、一个可编辑动作。事实、推断、建议分别标记。 |
| 无相关经验 | 显示「暂未找到可参考的历史记录」。可查看原复盘，继续人工记录。 |
| 来源变化或不可访问 | 对受影响建议标记「依据需重新核对」，显示当前可用信息。重新核对前停用该建议的采纳动作。 |
| AI 暂不可用 | 说明当前无法分析，提供手动重试及「复制分析上下文」。已有内容和草稿保留。 |
| 编辑、保存失败与保存成功 | 编辑态可返回建议。失败时原地保留草稿、可重试。成功态只出现一张行动卡，并明确仍待执行。有实际结果后从原路径记录。 |

## 设计交付与验收

交付一个可点击原型和四张可比较的首屏截图，画板为 **1440×900** 与 **390×844**，每个尺寸各有首页和事件详情。事件详情补齐分析结果、查看来源、编辑与保存、AI 不可用四种可点击状态。首页空态和无复盘状态可用同一组件的变体展示。输出页面、状态、控件和色彩的简要标注，方便后续实现。

- [ ] **首屏扫读**。首次打开首页或事件详情，在 5 秒内能指出当前事项、AI 能提供的帮助和应点的入口。5 秒是本稿提出的评审目标。
- [ ] **链接和文案一致**。首页主按钮进入原关键确认／记录入口，次级入口进入原事件库。事件中 AI 展开、来源返回和编辑保存能实际点通，复盘、规则和卡片入口仍可找到。
- [ ] **行为和状态准确**。能打开建议的来源并读出适用条件。关闭、取消、失败、重复点击均有可理解反馈。草稿、行动待执行和实际验证结果视觉上可区分。页面标清示例 AI 能力。
- [ ] **窄屏和键盘可用**。在 320–390 px、长中文标题和放大文字下检查横向溢出、换行、间距和底栏遮挡。用键盘完成查看来源、关闭与保存，关闭后焦点回到触发控件。检查文字对比和颜色以外的状态提示。
- [ ] **评审顺序**。先以浏览器和截图评审高保真，再按项目约定确认方向和验收。若进入生产开发，字体和图标优先复用本地资源，外部依赖使用固定版本。
