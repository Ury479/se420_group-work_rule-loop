## 问题陈述

我正在考虑一笔需要慎重判断的支出，希望在冷静期规则允许时提交我的用途、预算和替代方案，随后在同一条记录里看到建议并作决定。现有页面将待审记录放在「待 GPT 审核」，详情提供 Markdown 导出和外部结果回填。这个流程要求我自己发起外部审核、判断是否已有结果并回到 RuleLoop 录入，才能继续作决定。

**一句话**　需要审慎评估支出的 RuleLoop 用户，需要一次提交后就能在原记录查看进度和建议，因为当前跨工具交接由用户承担，容易让决策停在等待外部审核。

依据为本次反馈、截图和本地实现。实际用户情绪、发生频率及耗时尚未测量。「容易停在等待」是待通过真实使用验证的推断。[现有列表](../../../src/app/spending-review/page.tsx) · [现有详情](../../../src/app/spending-review/%5Bid%5D/page.tsx) · [现有提交和回填](../../../src/app/actions/spending-review.ts)

## 页面评审

- 桌面左侧用一个面板承接填报、查看建议和作决定，右侧集中显示审核记录及对应状态。手机上纵向排列，页首可以跳到审核记录。使用暖灰背景、深绿主按钮、单独的冷静期与失败状态色。
- 首屏露出支出名称、金额与币种、分类、用途。示意稿把状态、资金来源、替代方案折叠到「补充决策背景」。正式表单继续承接已有的订阅、状态、预算、主线和工具专项输入，随分类逐步展开。
- 正式页面把最佳状态决策协议、主线回归、消费参照物和消费价值换算放到辅助入口。现有详情、Markdown、复盘及旧记录可以继续访问。正式页面的固定文案通过现有中英界面字典呈现，辅助入口位于审核记录下方。本稿展示中文主流程。
- 原型点击「填入示例 → 提交审核」可体验排队、审核中、待人工确认。「在线课程年费」演示冷静期和复核，「设计素材订阅」演示超时后的原记录重试，「降噪耳机」可以直接试阅建议、选择决定并归档。示例建议固定，当前标签页存放演示记录。

## 建议采用的行为

| 用户操作或触发条件 | 页面反馈与后续动作 |
| --- | --- |
| 提交完整审核且规则允许 | 保存本条记录并自动加入 Hermes 审核队列，显示「等待审核」。用户可从审核记录再次打开。 |
| 规则要求冷静期 | 显示冷静期结束时间。结束后由用户确认「仍有需要」，然后自动入队。冷静期内不会发出模型请求。 |
| 审核任务开始 | 显示「审核中」。离开页面、刷新或重新登录后可查询同一任务。 |
| Hermes 返回有效建议 | 显示建议、主要理由和风险、替代方案及有依据时的延迟建议，进入「待人工确认」。 |
| 连接失败、超时或输出无法校验 | 显示可理解的失败原因，保留原输入，允许从同一记录重试。 |
| 用户保存决定 | 记录取消、延迟、缩减或替代、确认支出及理由，归档中可回看建议与决定。现有冷静期及高风险时段限制在服务端执行。 |

拟将「提交审核」视为本次请求的明确触发，服务端按现有风险引擎和冷静期判断何时入队。旧的「待 GPT 审核」记录继续可查，用户可在该记录主动发起 Hermes 审核，迁移时无需批量发送旧记录。模型建议和人工决定分别存储，模型输出只更新审核结果，页面操作只保存决定与付款状态。

## 免费模型与接入

建议复用现有 VPS 上的 Ollama 路线 `qwen3.5:2b-vps`。这里的免费指推理无按次 API 费用，使用现有 VPS 算力。部署文档记录过在 Mac 模型隧道断开时，通过 Hermes Webapp 得到合成回复，CPU 冷启动约 278 秒；本次未访问 VPS，RuleLoop 到 Hermes 的网络路径、真实结构化审核质量和耗时待实现后验证。使用审核专用的 Hermes 配置固定该本地路线，保留现有聊天配置，禁止自动切到付费提供商。[Hermes API 官方文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/api-server) · [Ollama 模型](https://ollama.com/library/qwen3.5:2b)

拟由 RuleLoop 服务端保存记录并交给持久任务执行，经私有网络调用已鉴权的审核端点。实际容器连通路径在 VPS 验证，Hermes 端口和密钥仅供服务端。审核只传本条记录所需的结构化字段，专用配置关闭工具和跨记录记忆。服务端校验结果及任务归属后保存，旧任务的迟到回复不能覆盖重试结果或用户已保存的决定。

## 施工后验收

- 用合成记录核验 RuleLoop → VPS Hermes → Ollama 实际调用与模型标识，覆盖无冷静期、冷静期未结束、冷静期后重新确认、模型停机和非法输出。
- 连续点击、刷新、进程重启、失败重试、迟到回包和跨账户访问分别检查。确认同一条记录只有当前有效审核可更新，人工确认受服务端状态限制。测试模型不可用时的失败记录和无付费回退。
- 在隔离的测试数据库验证桌面和手机流程、旧记录、界面中英切换、已有换算入口和高风险规则。按仓库说明补跑 `pnpm test:e2e --grep "localizes the spending comparison"`。

## 当前验收范围

可交互原型采用模拟审核、示意冷静期和示例记录。实际规则以服务端风险引擎为准。已用 Chromium 检查 1440 px 桌面和 390 px 手机布局，覆盖键盘进入表单、必填验证、后台状态切换、冷静期、失败重试、人工保存和刷新恢复。用户于 2026-11-11 确认此版布局与冷静期流程。正式工作区采用石白与靛夜配色，现行范围见[已确认需求](../../PRD-SPENDING-REVIEW.md)。
