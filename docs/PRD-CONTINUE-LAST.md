# RuleLoop · 继续上次

2026-11-11 · 恢复目标后，以带顶部热力图、习惯管理和暂存区的新版原型为实现基线。账号版入口位于首页「继续上次」，路由为 `/habits`。

## 1. 要验证的变化

离开 RuleLoop 或论文几天后，打开一次页面就能知道先做什么。有进展时随手留一条，下次用它接上。首个开发对象就是这次打卡功能，先把它做到自己在真实场景里能用一周，再观察至少一个月。

原型用两项示例习惯演示两种记录方式。每个账号同时最多养成两项。其他习惯放入暂存区，随时可以换回来。

| 线 | 开始时看什么 | 什么算一次进展 | 打卡时记录什么 |
| --- | --- | --- | --- |
| 项目开发 · RuleLoop | 当前迭代、当前下一步或最近产出 | 有一个能说清楚的实际产出，如可点击原型、已复现的问题、改动、自测结果 | 产出一句话必填，链接和下次先做什么选填 |
| 论文阅读 · AI / 计算机网络 | 当前论文、最近阅读位置（若有）、当前下一步或最近进度 | 实际推进过一段阅读、一个概念或一个疑问 | 已选论文时可以一键记一次，进度和下次先做什么选填 |

论文与项目各自有目标和记录。AI 与计算机网络是论文线内的两个方向，切换后显示对应论文的进度。泰拳、主题阅读、系统拆解、早起和雅思都可以作为新增习惯。模型树修剪按项目真实卡点触发。

## 2. 入口与接续

首页在现有「继续手头的事」区域加入一个「继续上次」入口。点击进入专页，最上方是打卡热力图，下面按行展示当前习惯的下一步或最近实际进度。桌面把标题、进度、记录动作放在同一行，手机按顺序展示。消费区原有「继续上次换算」始终指向该条消费记录。

1. 某条线有当前下一步时，优先展示用户保存的原话，下面附最近实际进度和发生日期。
2. 当前下一步为空时，突出最近实际进度，提供「写下这次先做什么」。这项操作更新当前动作，打卡数保持原值。
3. 开发保存一条新产出且下一步留空时，接续区回到新产出。论文保存一条新阅读且下一步留空时，接续区回到该论文最近阅读。上一轮动作仍可在相应历史记录中查看。只记了一次而没有文字时，显示记录日期与「已记录一次阅读」，已有阅读位置单独显示并标明来源时间。
4. 初次进入时，开发线提示「记录第一项产出」，论文线先选方向并写下当前论文，再开始记阅读。实际进度与下一步可各自为空。预览用示例记录展示两种接续状态。
5. 「最近记录」显示轨道、论文或项目上下文、日期、产出／进度及当时保存的下一步。阅读位置和下一步按对应论文保存，切换方向时随之切换。

### 最短操作

- **开发打卡**。打开「记录开发产出」→ 填产出 → 保存。空白或纯空格给出就地提示并保留其他输入。成功后立即显示新产出或新下一步。
- **论文打卡**。已选当前论文时点「记一次阅读」即可。想留位置或下一步时走「补充进度」再保存一条完整记录。
- **纠错**。保存成功后有清楚反馈。评审稿以撤销或重置示例支持重复评审。正式写入需能防止同一次提交因快速重复点击或重试而被计数两次。

### 习惯管理与热力图

- 「管理习惯」分为「正在养成」和「暂存区」，两区都可修改名称和删除。有空位时新增进入正在养成，满两项时新增进入暂存区。
- 可以将正在养成的一项直接暂存。有空位时直接启用暂存项。满两项时，用户先选要暂存的那一项，再确认「暂存并启用」。一次操作交换两项的状态，保留原记录、当前下一步和阅读上下文。
- 新增的通用习惯可一键打卡，或补充实际进度与下一步。确认删除后，该项从管理列表移除，既有打卡仍出现在最近记录。删除当前项会释放名额，由用户选择是否启用暂存项。
- 顶部热力图按周从左向右排列，共 13 周，包含当前周。每周从上到下是周一到周日，底部标注月份。用灰格表示零次，浅绿表示一次，深绿表示两次及以上。今天有描边，当前周尚未到达的日期留空。
- 默认合计正在养成的习惯，两项都启用时可切换查看单项。鼠标悬停、键盘聚焦或手机点按某格时显示完整日期和当天次数。打卡使用应用日期边界，默认是 `Asia/Bangkok`。论文阅读合计该习惯下各方向的实际阅读记录。
- 保存新打卡后更新对应日期，改名同步到筛选项。写下一步和记录待验证判断保持打卡计数。重新启用习惯后，恢复范围内的热力图历史。

## 3. 模型树试验

用在「已经做了一阵但不知道卡在哪里」的 RuleLoop 开发场景。首例是需求模糊，例如只知道要做打卡，却说不清隔了几天回来时应该展示哪条信息。

从开发线的「卡在哪？」打开短表单。留下当前判断、换看的视角（目标、使用场景、验收条件等）、下次怎么验证。例如把「打卡需求太散」缩小成「下一步为空时，最近产出够不够我重新开工」，然后用实际原型试一次。判断保存为「待验证」。用户可以显式将验证动作设为当前下一步。卡点记录本身与开发产出分开计数。模型树是否有效，由下次实际尝试后再判断。

## 4. 提醒假设与实用性检查

提醒可能在两个时点有用，仍是用户的估计。

| 时点 | 演示内容 | 点开后 |
| --- | --- | --- |
| 刚做完 | 「刚做完？留一条进度。」 | 去记录，进入对应记录表单 |
| 隔几天 | 「有空时，接着上次做。」 | 继续上次，看到当前动作或实际进度 |

原型由评审者手动触发「示例提醒」。真实使用试验先观察哪个时点有帮助、有没有点开和接上、是否感觉多余。做完的触发信号、间隔阈值、渠道与频率留待验证。没有记录只说明应用里没有记录，提醒文案据此保持中性。原型的提示只在预览里出现，评审数据保存在当前浏览器，本地存储受限时仅在打开期间有效。

| 检查点 | 看什么 |
| --- | --- |
| 第一周 | 在实际开发和论文阅读中各走通一次「回来 → 先做一步 → 留下进展」。记下哪一步费劲、是否愿意下次继续用。 |
| 首月 | 找至少一次自然中断。打开后能否立即说出并开始下一步？是已有下一步、最近进度还是提醒帮助接上的？尚无自然中断时继续观察。 |

## 5. 评审与验收

| 编号 | 检查操作 | 可接受结果 |
| --- | --- | --- |
| A1 | 从首页进入、返回，再从手机宽度进入 | 一个「继续上次」入口通向两条线，能辨认它与原有换算入口的区别 |
| A2 | 开发留空提交；再填写产出，下一步留空并保存 | 第一次停留表单并报错。第二次首页入口进入后能看到刚保存的产出，旧的下一步已退回历史 |
| A3 | 给开发设下一步；论文只点「记一次阅读」，再切方向 | 开发显示该动作。论文在已选文章时只点一次即记入，两个方向的上下文独立 |
| A4 | 打开「卡在哪？」并填写一条待验证判断 | 能看到判断与验证动作。只有显式采纳才更新当前下一步，产出次数保持原值 |
| A5 | 切换两种示例提醒，再点各自的动作 | 分别进入记录表单和接续页面。页面清楚显示演示状态，可关闭 |
| A6 | 以桌面和手机宽度查看；用键盘走一遍表单 | 标题与行动层级清楚，长文本可读，焦点可见，反馈和校验可辨认 |
| A7 | 悬停或点按热力图日期格，切换习惯，记录一次开发或阅读 | 紧凑周历位于顶部。日期提示显示完整日期和次数，总计与单项计数随记录更新 |
| A8 | 满两项时新增「泰拳练习」，再启用它 | 新项进入暂存区。启用时必须明确选择被暂存的一项，两项在一次操作内交换，热力图筛选列出当前两项 |
| A9 | 暂存一项再启用，分别改名和删除 | 暂存和改名保留原打卡、当前下一步及阅读上下文。删除后退出管理列表，打卡历史仍可回看 |

## 6. 账号版实现

- 账号初次进入时从空列表开始。添加习惯时可以选通用打卡、项目开发或论文阅读。工作区的最近记录展示最近 40 条，热力图与接续信息直接查询持久化记录。
- 习惯以账号内稳定标识关联打卡。[版本化迁移](../drizzle/0004_habit_checkins.sql)用两个可占用位置表达「正在养成」。位置允许 `1`、`2` 或空，按账号对非空位置做唯一约束。位置为空且未删除的习惯进入暂存区。删除标记保留历史关联。
- 新增、暂存和启用沿用 [账号鉴权](../src/lib/action.ts) 与 [账号事务](../src/db/index.ts)。启用交换在同一事务中先释放指定位置，再分配给待启用项。若另一设备已变更所选习惯，返回最新状态让用户重新选择。关联使用同账号外键和行级策略，打卡时再核验习惯仍处于启用状态。
- 打卡按 [账号日期边界](../src/lib/calendar.ts) 归日。校验需覆盖并发新增和交换、跨账号、重复提交、暂存后恢复、空态、刷新、论文上下文，以及本地中英文文案。数据库验收使用隔离测试库，浏览器回归从首页入口走通。原型提醒按独立试验验收。

临时 PostgreSQL 17.9 预验证覆盖了并发新增、满位交换、失败回滚、同账号关联和请求幂等。账号版的[数据库测试](../tests/database.test.ts)使用实际迁移及账号事务再次检查这些约束。[迁移回归](../tests/migrations.test.ts)从旧版本数据升级并重复应用迁移。
