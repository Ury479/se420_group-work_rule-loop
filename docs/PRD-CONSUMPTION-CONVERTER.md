# 消费价值换算与冲动拦截

## 1. 产品摘要

“消费价值换算与冲动拦截”是 RuleLoop 的一个本地优先功能。用户在发生或准备发生一笔冲动消费时，输入金额，系统将其换算成用户真正重视的 AI 工具、日常餐食或其他目标的可购买数量，并提供一个短暂的冷静期和可执行的替代行动。

该功能不负责评价消费是否合法、道德或“值不值”，也不把“没有花掉的钱”自动视为已经赚到的钱。它只完成三件事：

1. 把抽象金额转换成用户可感知的机会成本；
2. 在付款前制造一个低摩擦的暂停点；
3. 将“最终是否消费、是否转入目标预算”记录为 RuleLoop 的验证证据。

## 2. 背景与问题

用户已经发生过一笔约 `¥8,000` 的高风险冲动消费。单看金额难以形成即时制动力，但将其表达为“多少个月 Cursor、Claude、GPT 或其他 AI 工具”时，机会成本更具体。

当前问题包括：

- 冲动发生时，金额的长期价值不直观；
- 不同工具使用人民币、美元或其他币种，心算成本高；
- 订阅、充值额度和一次性购买不是同一种单位，容易误导比较；
- 事后懊悔不能直接转化为下一次可执行规则；
- 敏感消费数据如果被通知、日志或截图暴露，会产生额外隐私风险；
- “避免消费”与“真的把钱转入目标预算”容易被错误地合并。

## 3. 产品目标

### 3.1 主要目标

- 用户可在 30 秒内完成一次金额换算；
- 用户可在付款前 10 秒内理解至少 3 个机会成本；
- 用户可启动冷静期，并选择一个最小替代行动；
- 用户可在冷静期结束后记录“已消费 / 已放弃 / 部分消费”；
- 系统可区分“避免的支出”和“实际转入 AI 预算的金额”；
- 敏感记录默认只保存在本机，并支持中性化显示。

### 3.2 成功指标

首版只使用可解释指标，不使用连续签到、积分或羞辱性统计。

| 指标 | 定义 |
|---|---|
| 换算完成率 | 打开换算器后成功生成结果的会话占比 |
| 冷静期启用率 | “正在考虑”记录中启动冷静期的占比 |
| 冲动放弃率 | 冷静期结束后标记为“已放弃”的占比 |
| 保护金额 | 已放弃记录的计划消费金额总和 |
| 实际转向金额 | 用户明确确认已转入目标预算的金额总和 |
| 规则想起率 | 后续触发时想起该规则的验证次数 / 触发次数 |

### 3.3 非目标

- 不提供投资、借贷或财务收益建议；
- 不自动购买 AI 套餐或代用户转账；
- 不抓取、展示或推荐色情服务、商家、价格、地点或排名；
- 不根据消费类别诊断成瘾或心理疾病；
- 不用“省下的钱”鼓励用户立刻购买并不需要的 AI 套餐；
- P0 不接入银行卡、支付宝、微信支付或账单读取；
- P0 不依赖实时汇率或第三方价格 API。

## 4. 目标用户与核心场景

### 4.1 目标用户

- 单用户、自用、本地优先；
- 已经有明确的学习、创作或 AI 工具预算目标；
- 会出现高金额、短决策时间的冲动消费；
- 愿意在冲动前或事后进行最短记录。

### 4.2 核心场景

#### 场景 A：付款前拦截

用户准备支付 `¥2,000`，打开换算器，看到它相当于约 14.3 个月 Cursor Pro、12.6 个月豆包高阶版或 6.7 个月 Kimi。用户启动 2 小时冷静期，关闭付款页面。

#### 场景 B：事后复盘

用户已支付 `¥8,000`，将记录状态设为“已经发生”。系统显示机会成本，但不得把这 `¥8,000` 计入保护金额。该事件进入 RuleLoop 复盘，并可形成下次触发时的规则。

#### 场景 C：避免后转向

用户原计划花费 `¥1,400`，冷静后放弃，随后手动将 `¥500` 放入 AI 预算。系统记录保护金额 `¥1,400`、实际转向金额 `¥500`，两者不混淆。

## 5. 产品原则

1. **先暂停，后计算**：结果页最重要的行动是“开始冷静期”，不是“去购买 AI”。
2. **事实与评价分离**：使用“计划金额”“已经发生”“机会成本”，不使用“堕落”“浪费”“失败”等词。
3. **比较必须同口径**：月订阅按月数显示，充值包按包数显示，餐食按顿数范围显示。
4. **价格可编辑且有快照**：历史结果必须保留当时价格与汇率，不随目录更新漂移。
5. **隐私默认开启**：敏感类别可显示为“私密消费”或用户自定义别名。
6. **证据高于激励**：只记录是否想起、是否遵守、结果是否改善，不使用奖杯、排行榜或签到。
7. **避免替代性过度消费**：机会成本是比较单位，不是购买建议。

## 6. 信息架构

该功能嵌入现有 RuleLoop，而不是增加新的底部导航项。

```text
首页 /
├── 主行动：进行一次消费换算
├── 最近轨迹：显示冷静期或结果
└── 保护金额摘要（存在有效数据时）

快速记录 /record
└── 损失类型 = 金钱
    └── 打开消费换算器

消费换算 /convert
├── 输入
├── 换算结果
├── 冷静期
└── 最终结果

事件详情 /events/[id]
└── 财务影响与换算快照

规则详情 /rules/[id]
└── 触发时再次换算

成长档案 /archive
└── 保护金额与实际转向金额（派生）
```

## 7. 用户流程

### 7.1 付款前流程

```text
输入金额
  → 选择“正在考虑”
  → 选择比较清单
  → 查看换算结果
  → 开始冷静期
  → 选择最小行动
  → 冷静期结束
  → 记录已放弃 / 部分消费 / 已消费
  → 可选：记录实际转入目标预算
  → 形成一次规则验证
```

### 7.2 事后流程

```text
输入金额
  → 选择“已经发生”
  → 查看换算结果
  → 保存为高影响事件
  → 进入复盘
  → 关联或创建“高风险消费前先换算并等待”的规则
```

## 8. 功能需求

### 8.1 金额输入

- 默认币种为人民币 `CNY`；
- P0 支持 `CNY`、`USD`，保留扩展 `THB` 的数据能力；
- 金额必须大于 0，最多保留两位小数；
- 用户必须选择状态：
  - `considering`：正在考虑；
  - `spent`：已经发生；
- 类别为可选字段，默认显示中性选项：
  - 私密消费；
  - 娱乐；
  - 购物；
  - 餐饮；
  - 其他；
- 用户可在本机设置更具体的私密别名，但通知和首页默认不展示具体别名。

### 8.2 价值目录

每个目录项包含名称、计费类型、价格、币种、计费单位、是否启用和来源备注。

首版预置用户提供的数据，全部标记为“用户录入，未自动核验”：

| 项目 | 类型 | 原始价格 | 规范化价格 |
|---|---|---:|---:|
| GPT Pro | 月订阅 | USD 100 / 月 | CNY 700 / 月 |
| 豆包个人高阶版 | 月订阅 | CNY 159 / 月 | CNY 159 / 月 |
| v0 | 月订阅 | CNY 150 / 月 | CNY 150 / 月 |
| Kimi | 月订阅 | CNY 300 / 月 | CNY 300 / 月 |
| 智谱官方额度 | 月度额度 | CNY 300 / 月 | CNY 300 / 月 |
| Cursor Pro | 月订阅 | USD 20 / 月 | CNY 140 / 月 |
| Claude Max | 月订阅 | USD 100 / 月 | CNY 700 / 月 |
| Claude Pro 年付月均 | 月订阅 | USD 17 / 月 | CNY 119 / 月 |
| GPT API 额度包 | 充值包 | USD 200 / 包 | CNY 1,400 / 包 |
| 日常一顿饭 | 区间单位 | CNY 40–60 / 顿 | CNY 40–60 / 顿 |
| 面膜 | 一次性单位 | CNY 170 / 份 | CNY 170 / 份 |

默认汇率使用用户已给出的心算基线：`1 USD = 7.00 CNY`。汇率必须可编辑，并在每次换算中保存快照。

### 8.3 换算结果

系统同时提供两种结果：

1. **单项等值**：该金额分别等于每个已选目录项的数量；
2. **目标组合**：用户选择一个或多个项目以及目标周期，系统显示覆盖成本和余额。

计算公式：

```text
normalizedAmount = inputAmount × inputCurrencyToCnyRate
normalizedUnitPrice = unitPrice × unitCurrencyToCnyRate
equivalentQuantity = normalizedAmount ÷ normalizedUnitPrice
wholeUnits = floor(equivalentQuantity)
remainder = normalizedAmount - wholeUnits × normalizedUnitPrice
```

区间项目：

```text
minimumCount = floor(normalizedAmount ÷ maxUnitPrice)
maximumCount = floor(normalizedAmount ÷ minUnitPrice)
```

显示规则：

- 订阅显示 1 位小数月数，并补充“完整 X 个月 + 余额 ¥Y”；
- 充值包显示 2 位小数包数，并补充“完整 X 包 + 余额 ¥Y”；
- 餐食显示整数范围；
- 金额统一显示 2 位小数，列表摘要可省略 `.00`；
- 不把“额度”错误描述为 token 数量，除非用户录入了明确 token 单价；
- 结果必须显示“价格和汇率来自本次快照”。

### 8.4 冷静期

- 仅 `considering` 状态显示；
- 快捷选项：15 分钟、2 小时、24 小时、自定义；
- 用户选择一个最小行动：
  - 关闭当前付款页面；
  - 离开当前场景；
  - 联系可信任的人；
  - 把金额暂存到目标预算；
  - 自定义；
- 本地倒计时不得阻塞应用；
- P0 只在应用内显示到期状态，不发送包含敏感类别的系统通知；
- 冷静期内再次打开记录时，首先显示剩余时间和原始换算快照。

### 8.5 最终结果与资金去向

冷静期结束后可记录：

- `avoided`：已放弃；
- `partial`：部分消费，必须填写实际金额；
- `spent`：已消费；
- `unknown`：暂不记录。

计划金额保留原币，资金去向统一用人民币。外币计划按本次保存的汇率折合人民币。实际消费和实际转向由用户以人民币填写。「已消费」留空时沿用计划的人民币金额。

派生金额（均以人民币分计算）：

```text
protectedAmount =
  avoided ? plannedAmount :
  partial ? max(plannedAmount - actualAmount, 0) :
  0
```

实际转向金额必须由用户单独确认，且满足：

```text
0 <= redirectedAmount <= protectedAmount
```

“保护金额”不得显示为账户余额，不得暗示已经存入或赚得。

### 8.6 RuleLoop 集成

- `spent` 且达到高影响门槛时，创建或关联一个事件并进入待复盘；
- `considering` 完成最终结果后，创建一次事件或关联现有事件；
- 若用户已有相似规则，优先关联而不是重复创建；
- 建议规则文案：

> 当我准备进行超过自定义阈值的非计划消费，并注意到自己想立刻付款时，先打开价值换算，等待至少 2 小时，再决定是否支付。

- 最终结果保留消费决定和资金去向。冷静期显示计时状态，保存后的状态以结果保存时间为准。
- 规则验证使用用户单独提交的反馈。关联规则、计时到期或支出低于计划都只记录各自的事实。

### 8.7 历史与摘要

- 历史按时间倒序；
- 默认标题显示中性类别和计划的原币金额；
- 支持查看当时价格、汇率、结果、冷静期和最终状态；
- 首页最多显示一个与此功能相关的主行动；
- 成长档案可展示：
  - 触发次数；
  - 已完成冷静期次数；
  - 保护金额；
  - 实际转向金额；
- 成长档案的「支出低于计划」按保护金额大于零的明确结果统计。「有帮助的规则」按统计期内用户评为有帮助的启用规则统计。
- 已经发生的记录以原始支出及其汇率快照计入人民币历史支出。部分消费或最终确认已消费的记录，以人民币实际消费额计入。
- 旧版部分消费的人民币实付与转向金额保留，保护金额按原汇率重算。旧版已消费的外币记录若无法确定实付币种，保留原始数据，在详情及汇总提示待核对。

## 10. 界面规格

视觉基线继承 RuleLoop 的 Decision Trace：

- 冷静、诚实、非责备、可行动；
- 使用现有 Cold Paper、Deep Ink、Action Cobalt、Proof Teal、Signal Amber；
- 不使用霓虹、赌场式数字滚动、奖杯、火焰或“战胜欲望”等刺激性表达；
- 金额是页面最大数字，但“开始冷静期”是唯一主行动；
- 价格目录使用结构化行，不做拥挤的订阅卡片墙；
- 手机端优先，桌面端增加价格快照与规则上下文，不增加更多主操作。

### 10.3 可访问性

- 所有输入必须有可见标签；
- 金额错误要说明修正方式；
- 不只用颜色表达“正在考虑 / 已发生 / 已放弃”；
- 触控区域至少 44×44px；
- 数字使用等宽字体，但屏幕阅读器标签必须读出完整币种和单位；
- `prefers-reduced-motion` 下不播放数字递增动画；
- 隐私模式下页面标题、最近任务和导出摘要不得出现敏感类别原文。

## 11. 隐私与安全

- 数据默认写入本地 SQLite；
- 不将换算金额、类别或备注发送给第三方；
- P0 不接入 AI 自动分析；
- 调试日志不得记录输入金额、类别别名或备注正文；
- 导出必须由用户主动触发；
- 导出前明确提示可能包含敏感财务数据；
- 支持删除单条换算记录，并说明对关联事件、复盘和验证证据的影响；
- 系统通知若未来实现，只能使用“你的冷静期已结束”等中性文案。

## 12. 发布范围

### P0：可用闭环

- 人民币/美元输入；
- 可编辑价值目录；
- 单项等值计算；
- `¥8,000` 历史记录；
- 冷静期；
- 最终结果；
- 保护金额与实际转向金额分离；
- RuleLoop 事件和验证关联；
- 本地隐私模式。

### P1：日常可用

- 自定义组合目标；
- 目录导入导出；
- 更细的阈值和默认冷静期；
- 受控的本地通知；
- 统计周期筛选。

### P2：条件性扩展

- 经用户明确同意后获取实时汇率；
- 价格更新提醒；
- 跨设备同步；
- 支付账户只读导入。

## 13. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 换算反而促使购买过多 AI 工具 | 明确“等值不是购买建议”，主行动始终是冷静期 |
| 用户误以为保护金额是真实余额 | 与实际转向金额分栏，使用不同标签和解释 |
| 价格过期 | 可编辑目录、更新时间和换算快照 |
| 敏感类别泄露 | 默认中性标签、无敏感通知、日志脱敏 |
| 过多比较导致决策疲劳 | 默认只选 3 个锚点，其余折叠 |
| 已发生支出被错误计为节省 | `spent` 永远不产生保护金额 |
| 用户用虚假的放弃记录美化结果 | 指标只作个人证据，不提供奖励或排行榜 |

## 14. 待产品确认

这些问题不阻塞 P0 规格，但应在高保真设计评审前确认：

1. “智谱官方额度”是否是用户所说“Zip code 官方”的准确名称；
2. GPT Pro `USD 100/月` 是用户的个人换算锚点，还是需要更名为其他 GPT 套餐；

4. 首页是否显示保护金额，还是只在成长档案显示；
