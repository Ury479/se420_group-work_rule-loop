# v0 页面重构提示词：让投入回到主线结果

版本：v0.2 · 2026-09-28  
使用：把下面整个代码块粘贴到正在维护的 v0 项目；可一并上传 `PRD-CHECKPOINT-VALIDATION.md`。提示词已经包含产品意图、真实案例、页面改动和验收路径，不依赖 v0 阅读本次聊天。

本次重写重点：从抽象的四段表单改为“带着原始期待与证据，找出一个尚不能判断的问题，并推动最小验证”的现有页面重构。具体布局和文案是设计提案，不冒充已验收界面。

```text
请重构当前项目的相关页面，让现有 RuleLoop 围绕下面的产品意图工作。不要只给建议、PRD、宣传页或另起一套孤立的 demo。先检查当前项目，沿用已有组件和真实能力；遵守文末设计到实现的阶段要求。

一、先理解我为什么要改这个产品

这是我的个人工具。开发已经花了一到两个月，实际用过不到三次。我担心自己在反复开发一个可有可无的东西。
其中消费换算确实帮过我：我比较一笔钱的不同用途，发现 Cursor 虽然可换来更长时间，但已有额度够用。后来隔了一周才购买 GPT。实际获得的帮助主要是设计模式和动态规划学习，产品工作只有少量推进。
我不缺 AI 的分析。我随时可以找 AI 聊天，但要先自己想起复盘、重新组织背景、整理 Obsidian 材料。换一个 AI 可能又得到另一套说法。我缺少持续保存的个人依据，以及在约定时刻把我带回问题的机制。
我不愿每天填记录。我愿意在约定节点集中看一遍已有材料，确认哪些结果是真的，哪些还不知道，再决定一个小动作。

请让产品帮助我回答：
“我当初为什么投入？后来得到什么？它和当前主线有什么关系？还有哪件事不知道，所以现在不该急着下结论？下一步最少做什么就能知道更多？”

二、产品必须让人感受到的价值

我打开页面，不应先看到四个空白输入框或一堆模块入口，而应该看到一个具体的、还没判断清楚的问题，以及继续判断所需的上下文。
页面要记住“过去的我为什么这样决定”，把“现在已有的结果”放到旁边，让未知成为下一步验证的来源。
“计划、行动、记录、复盘”是后台组织逻辑；“期待、结果、未知、决定”是用户能读懂的核心内容。不要为了模型完整再建四套模块。
消费换算继续保留，它提供购买前的比较；核心向后延伸到真实结果。消费只是第一个入口，不要求每张卡都有金额。

这次亮点必须在页面里体现：
1. 不用重新解释背景，就能开始一次判断。
2. 能看见哪条结果回应了哪条期待，哪些期待暂时没有依据。
3. 从某条未知直接形成一次最小验证，完成后能回来继续判断。

三、首页主案例：用产品检验它自己是否有用

这是本轮最重要的案例。请用它贯穿首页、回访和历史，让我直观看出重构是否理解我的问题。
主题标题：“这个工具值得继续开发吗？”
当前主线：“先解决自己的一个真实问题，再决定是否继续投入开发。”

当初的期待：
“帮我更有依据地安排重要支出，服务长期计划。”

你验证的结果：
- “前后使用不到三次。”来源：用户自述。
- “消费换算帮助过一次 GPT 购买决策。”来源：用户自述；这是一次帮助，不是已证明持续有效。
- “开发投入约一到两个月。”来源：用户自述；这是背景，不是必须继续开发的理由。

未知的信息：
- “它能否持续提供帮助？”
- “约定节点发起回访，是否比我自己用 AI＋Obsidian 更省事？”

这次的决定：先进行最小可行性验证。
“先完成一次真实回访，观察是否补出了原本遗漏的信息，并产生一个具体下一步，再决定是否继续开发。”

注意：未知仍未解答；不要显示产品已有效、已验证成功、节约多少时间或已改善多少百分比。节点日期未由用户指定，显示“待约定”，不要伪造逾期。演示到期状态可用独立预览控制切换，不能当成真实提醒。
案例标明“示例｜依据用户自述整理”，不要写入真实用户历史。

四、现有页面如何改

请先给出实际路由映射表，然后直接完成当前阶段允许的页面修改。优先复用实际项目中的页面，不机械创建以下路径。当前参考项目曾使用 /、/record、/review、/review/[id]、/rules、/rules/[id]、/archive；v0 项目可能不同，必须以当前代码为准。

A. 首页：从功能菜单改为“我现在要判断的事”
- 首屏以问题“这个工具值得继续开发吗？”为核心，显示一行当前主线。
- 问题下直接露出最关键的反差：“已经帮助过一次，但持续价值还不知道。”它必须能追溯到下面的事实。
- 期待与当前结果同屏对照；未知以待回答问题呈现，不藏到详情页末尾。
- 只突出一个随状态变化的操作：未约定→“约一次真实回访”；等待中→“查看这次验证”；到期→“开始这次回访”；回访未完→“继续判断”。
- 明确显示为什么现在需要/不需要回访：日期、用户确认的里程碑或兜底日期。
- 次级保留“消费换算”和历史入口；取消原来记录/复盘/规则/档案四个并列大入口的主导地位。
- 不使用装饰性的总金额、遵守率、连续天数、经验值或卡片总数来充满页面。

B. 原记录入口：改成“留下一个期待，约好回来看看”
- 一个短流程：我现在在推进什么 → 我期待这次投入带来什么 → 什么时候回来判断。
- 前两项复用现有主线和换算上下文；能带入就不要再填。
- 支出、金额、资源状态、材料链接作为可选补充，不把日常使用变成记账。
- 节点支持明确日期/时间/时区，或用户确认的里程碑＋兜底日期。
- 保存后展示完整句子，例如“在［节点］，回来看看［期待］是否有了依据”，日期未选时不允许假称约定成功。

C. 原复盘页：改成“带着依据回来判断”的工作台
- 四个固定标题必须保留：当初的期待、你验证的结果、未知的信息、这次的决定：先进行最小可行性验证。
- 不做四张完全一样的大卡片或四个必填 textarea。期待是保留的原文，结果是可核对的事实条目，未知是问题列表，决定是一个可以执行的小实验。
- 桌面端将期待和结果相邻展示；手机端按同一条期待组织相关结果，减少来回滚动。四段标题仍有清晰的阅读顺序。
- 每条结果可标记回应哪条期待，显示来源类型；允许“有关联”“尚无依据”“关联待确认”，不要用AI评分替代判断。
- 结果区域先展示已关联内容，用户可确认、修正或移除；另给“粘贴已有材料”和“补充一句结果”入口。没有接入资料源时显示“尚未关联材料”，不假装自动读取了笔记。
- 允许保留“我还不知道”，不强迫得出成功/失败结论。用户自述可作为一种依据，但与可查看的作品、笔记来源分开标明。
- 用户点击一条未知旁的“先验证这个问题”，将该问题带入决定区域。
- 决定区域只问：做哪一个动作、看到什么才算获得了依据、何时回来。不生成完整项目计划。
- 主操作“保存这次决定并约好回访”；次级操作为改约、暂停、结束。结束时保留理由，不强迫所有事情都开始下一轮。

D. 原档案页：改成“我的判断怎样改变了”
- 按主题查看期待、每轮结果、未知、决定和下一节点的变化。
- 第一眼能读出“原来认为……后来发现……所以决定先……”，所有句子来自记录，不能伪造AI洞察。
- 打开任一结论能看到依据；目标变化保留时间与原因，不改写原始期待。
- 不把记录数量当成长，不做没有真实数据的趋势图。

E. 消费换算页：保持已有核心能力，补上后续
- 换算结果后增加上下文动作“这笔投入，我想验证什么？”带入金额和当时选项，让用户留下期待与节点。
- 允许记录“已有工具够用，先不买”，购买不是唯一成功路径。
- 比较更长使用时长不自动得出更高价值，需联系当前需求。
- 如果当前项目没有可用换算器，明确缺失，先保留入口规格；不要为了这次重构顺带重做整套换算业务。

F. 规则库等旧页面
- 保留已有访问和数据，降低主导航优先级，提供次级“历史功能”入口。
- 不要求完成规则、错误分类或标签维护后才能开始验证。不要删除旧路由，也不要把旧规则历史静默转换成新证据。

五、最重要的交互：未知真的进入下一步

请让这条链路可操作：
首页“这个工具值得继续开发吗？”
→ 进入四段内容，看到已有事实和两个未知
→ 选择“约定节点回访是否更省事？”
→ 将问题带入“先完成一次真实回访”的动作草稿（清楚标记建议，允许用户修改）
→ 用户写明观察点：是否补出遗漏信息、是否形成一个具体下一步，也记录整理材料的负担
→ 用户约定节点
→ 状态变成等待，下次回来仍能看见原始期待和这次决定
→ 完成新一轮后保留旧轮次，不覆盖历史。

应用内到期状态不能冒充主动提醒。为应用外启动设计清楚的设置状态；日历可作为候选渠道，导出不等于已添加，已添加不等于送达。没有通知服务时如实显示能力边界。首轮真实试用必须验证一次实际可到达的提醒，但本次页面任务不代用户创建外部提醒。
不要重复催促或制造逾期惩罚。用户能改约和暂停；外部提醒不能同步撤回时提示手动处理。

六、另一个场景：证明它不只适用于开发复盘

提供可切换的次级演示“GPT 这笔投入实际帮了我什么？”：
- 期待：学习、作业、产品思考与设计方面的支持。
- 用户报告的结果：设计模式、动态规划学习推进；产品少量推进；泰拳项目暂缓。
- 未知：下一阶段的任务需要什么，已有工具能否满足，哪些帮助能找到具体材料。
- 下一步不默认续费/取消，而是由用户选择一个未知、明确最小验证。
不编造套餐价格、发生日期、任务完成数、因果关系或收益率。

七、视觉表达与阶段要求

延续当前项目已确认的视觉风格；参考资产可用时继承克制的深色与金色主操作。视觉重点是“问题 → 对照 → 未知 → 动作”，不是四个同权色块。使用真实中文内容，关键差异靠排版、位置、简洁标注表达，不靠仪表盘、徽章堆叠或大面积渐变。
移动端首屏能读懂当前问题和下一步；桌面增加对照空间与来源上下文。支持键盘、可见焦点、语义表单、非颜色状态与减少动效。

遵守现有 AGENTS.md 的设计优先要求：需求与信息架构 → 视觉高保真 → 浏览器/截图评审 → 用户确认或明确视觉验收 → 生产页面开发。
需要使用 guizang-ppt-skill 时先读取；若环境不可访问，如实报告，不冒充已使用。现有资产只能作为基线，不能把新增布局自动视为已通过验收。
第一阶段交付必须让用户在预览里看到上面指定页面的改版和完整交互路径，不能只返回抽象设计说明，也不能另建一个与真实页面毫无对应关系的展示站。未到生产阶段时可在隔离预览中复用现有页面组件，清楚列出对应页面改动。
如果当前改版已有明确视觉验收，继续修改对应生产页面；没有验收则停在可评审的页面预览，列出剩余实现。未经授权不部署、不上传私人记录。
修改 Next.js 代码前阅读实际安装版本的 node_modules/next/dist/docs/。依赖固定版本，避免 latest CDN。

八、交付与验收

交付：实际路由前后映射、改动后的页面预览、关键状态截图、完成的交互与未完成能力、下一步。
数据层遵循现有能力，未连接持久化就标记演示；不显示虚假的“已永久保存”“已自动读取”“提醒已发送”。演示数据不得混进真实记录。原型状态切换放在独立预览控件。

请逐项验证：
1. 不解释背景也能从首页读出当前问题、已有依据和尚未知的部分。
2. 记录不超过三次不能被显示为“已证明持续有效”；没有材料不能被显示为“没有进展”。
3. 点击未知能带入一个具体最小验证，并能约定、改约、暂停或结束。
4. 不每日记录也能完成回访；不连接AI也能完成核心判断。
5. 不把未选定日期当成已约定，不把节点到期当作实验完成。
6. 历史能看到每一轮判断的依据与变化，旧记录不被覆盖。
7. 消费换算仍可进入，与主线连通，旧功能仍可访问。
8. 在390px和桌面宽度检查上述真实内容、按钮、长文溢出和键盘操作；无法运行的检查明确列出。

最后判断页面是否成功，请用这个问题：
“它是否减少了我重新组织背景的负担，并把一个尚未解决的问题变成一次我知道如何开始的验证？”
不要以页面更漂亮、卡片更多或加入新AI作为完成标准。
```
