# RuleLoop Design System — Decision Trace

> 版本：v0.2 · 2026-07-21  
> 适用：P0 的 8 个路由页面  
> 视觉目标：克制地面对错误，清楚地指向下一步，用证据展示改变

---

## 1. 主题、受众与任务

- **主题**：个人经历从事实变成规则、再变成行为证据的过程。
- **受众**：产品所有者本人，移动端高频、短时使用。
- **单页原则**：每页只承担一个任务，只存在一个最高视觉权重的行动。
- **情绪基调**：冷静、诚实、非责备、可行动；不是疗愈日记，也不是企业数据面板。

## 2. 设计探索与选择

### 被放弃：卡片式功能大厅

```text
┌─────┐ ┌─────┐
│记录 │ │复盘 │
└─────┘ └─────┘
┌─────┐ ┌─────┐
│规则 │ │档案 │
└─────┘ └─────┘
```

问题：它可以属于任何效率工具，没有表达“经历如何转化为行动”。

### 被放弃：纸质反思日记

```text
日期 / 长文本 / 手写装饰 / 引语
```

问题：过度强调记录和情绪，会弱化约束、触发和验证。

### 采用：Decision Trace 决策轨迹

```text
    ● 发生了什么
    │
    ◆ 哪里本可不同
    │
    ■ 下次先做什么
    │
    ✓ 结果是否改善
```

结构本身就是产品逻辑。节点形状表达阶段，脊线表达可追溯关系，状态变化依靠形状、文案和颜色共同传达。

## 3. 标志性元素：Loop Spine

Loop Spine 是全产品唯一被允许高辨识度出现的视觉元素：

- 首页：显示当前闭环停在哪个节点；
- 事件详情：连接事件、复盘、规则和验证；
- 复盘工作台：作为三步进度；
- 规则详情：从规则延伸到验证证据；
- 成长档案：作为时间线主轴。

规格：

- 线宽：移动端 2px，桌面端 3px；
- 未完成：`--trace-muted`，短虚线；
- 当前节点：`--action-cobalt`，外圈 4px 柔和 ring；
- 已完成：`--proof-teal`，实线；
- 节点：事件圆形、决策菱形、规则方形、验证勾形；
- 动效只在首次进入时从上到下绘制一次，240–320ms；
- `prefers-reduced-motion` 下直接呈现最终状态。

除 Loop Spine 外，不叠加大面积渐变、噪点、玻璃效果或漂浮装饰。

## 4. 颜色令牌

| 名称 | Hex | CSS 变量 | 用途 |
|---|---|---|---|
| Cold Paper | `#F2F6F5` | `--surface-paper` | 页面背景，冷静而不临床 |
| Deep Ink | `#172623` | `--ink-deep` | 主文字与深色控件 |
| Action Cobalt | `#3157C8` | `--action-cobalt` | 唯一主行动、当前节点 |
| Proof Teal | `#14786B` | `--proof-teal` | 已验证、完成和改善证据 |
| Signal Amber | `#C77918` | `--signal-amber` | 风险信号、高价值准入 |
| Impact Red | `#B94743` | `--impact-red` | 高影响、错误和危险操作 |

辅助色：

| 名称 | Hex | 用途 |
|---|---|---|
| Surface | `#FFFFFF` | 输入区和提升层 |
| Soft Wash | `#E4ECE9` | 次级区块 |
| Trace Muted | `#A8B8B3` | 未完成脊线 |
| Border | `#CBD7D3` | 分隔和控件边界 |
| Muted Ink | `#60716C` | 次级文字 |

规则：

- 主操作只使用 Action Cobalt；
- Proof Teal 只表示有证据的完成，不表示一般“成功”；
- 普通存档使用中性色，不给人失败感；
- 高影响和危险删除都可用红色，但必须配合文字与图标；
- 页面同时出现的强调色不超过两种。

## 5. 字体系统

### 字体角色

- **叙事与结论**：`Noto Serif SC` / `Songti SC` / `STSong`。用于页面主标题、核心规则句和证据结论。
- **界面与正文**：`Noto Sans SC` / `PingFang SC` / `Microsoft YaHei`。用于控件、说明、列表和长文本。
- **时间与数字**：`SFMono-Regular` / `JetBrains Mono` / `ui-monospace`。只用于时间、百分比和事件编号。

P0 优先系统字体，避免运行时请求 Google Fonts。正式发布前再决定是否自托管开源中文字体。

### 字号

| Token | Mobile | Desktop | 用途 |
|---|---:|---:|---|
| `display` | 30/38 | 42/50 | 首页核心行动句 |
| `h1` | 24/32 | 32/40 | 页面标题 |
| `h2` | 18/26 | 20/28 | 区块标题 |
| `body` | 15/24 | 16/26 | 正文 |
| `label` | 13/18 | 13/18 | 标签和辅助说明 |
| `data` | 13/18 | 14/20 | 时间和数值 |

中文不使用全大写字距效果。英文眉题仅在确有语义时出现，不作为装饰。

## 6. 布局系统

### Mobile 375–767

```text
┌────────────────────────┐
│ 24px page inset        │
│ ┌────────────────────┐ │
│ │ title / next action│ │
│ └────────────────────┘ │
│   ●                    │
│   │  main content      │
│   ◆                    │
│   │                    │
│   ■                    │
│                        │
│ safe bottom / nav      │
└────────────────────────┘
```

- 页面水平边距 20px；
- 内容最大宽度 560px；
- 区块间距 28–36px；
- 表单操作可固定底部，但必须预留安全区和内容 padding；
- 卡片只用于需要边界的对象，不用卡片包裹每个段落。

### Desktop ≥1024

```text
┌────────┬──────────────────────────┬──────────────┐
│ 72px   │ main 640–760px           │ context 280px│
│ rail   │                          │              │
│        │ Loop Spine + content     │ source/status│
└────────┴──────────────────────────┴──────────────┘
```

- 左侧导航轨 72px；
- 主内容区 7 列，保持易读行宽；
- 右侧上下文区 3–4 列，展示来源、状态或快捷解释；
- 表单不拆成多列输入；桌面端增加上下文，而不是增加认知负担。

## 7. 间距、圆角与阴影

### Spacing

`4 / 8 / 12 / 16 / 20 / 28 / 36 / 48 / 64`

### Radius

- 输入和按钮：10px；
- 对象容器：14px；
- 状态胶囊：999px；
- Loop 节点不使用圆角替代语义形状。

### Shadow

- 默认不使用阴影区分普通区块；
- 浮层：`0 12px 36px rgb(23 38 35 / 12%)`；
- 固定底部操作区：顶部 1px 边界 + `0 -8px 24px rgb(23 38 35 / 6%)`；
- 主行动不使用发光阴影。

## 8. 核心组件

### NextAction

首页最高权重区块。包含一句动作标题、原因和一个按钮。一次只展示一个动作。

### TraceNode

包含阶段形状、标题、时间、状态和可选跳转。节点与 Loop Spine 组成可追溯轨迹。

### EventRow

不使用厚重卡片。左侧影响/重复标识，中间事实与时间，右侧状态和箭头。

### RuleStatement

规则以完整句子优先展示：

> 当准备提交重要文件，并注意到自己在赶时间时，先重新打开附件确认内容和版本。

详情字段用于编辑，用户首先看到的是可执行句，而不是数据库字段列表。

### EvidenceStamp

只用于真实验证：待观察、有效、需要调整。由图标、文字和边框共同表达，不使用奖杯或彩带。

### DecisionGate

记录提交后解释为什么“只存档”或“进入复盘”。它显示判断依据，并允许返回修改事实。

## 9. 控件规范

### Primary Button

- 高度 48px；
- Action Cobalt 背景；
- 动词开头：“保存事件”“开始复盘”“启用规则”“记录验证”；
- 每页最多一个主按钮。

### Secondary / Quiet Action

- 透明背景 + Deep Ink 文字；
- hover 使用 Soft Wash；
- “编辑”“复制”“稍后处理”等使用此级别。

### Inputs

- 白色或透明背景，1px Border；
- focus 使用 2px Action Cobalt + 2px 外圈；
- 标签始终可见，不以 placeholder 代替；
- 错误说明具体指出如何修改；
- 文本域随内容增长，避免内部滚动。

### Choice Chips

- 最小触控高度 40px；
- 选中态使用颜色、图标和字重三重变化；
- 不使用 emoji 作为类别图标。

---

## 10. 动效

唯一编排动效是 Loop Spine 的一次性绘制。其他交互只允许：

- hover/focus 颜色转换：140–180ms；
- 页面内状态切换：180–220ms；
- 保存成功的节点完成反馈：240ms；
- 不使用持续漂浮、弹跳、视差和全局入场动画；
- 减少动态模式下移除位移和路径绘制。

---

## 11. 文案声音

- 直接描述事实，不评判人格；
- 普通存档是正常结果：“已存档，这次不需要创建规则”；
- 解释准入原因：“这件事曾经发生过，值得复盘一次”；
- 空状态给动作：“还没有待复盘事件。记录重复或高影响事件后会出现在这里”；
- 不使用“坚持”“打卡”“战胜自己”等泛化激励；
- 不用英文系统术语面向用户。

---

## 12. 禁止模式

- 功能入口四宫格作为首页主体；
- 大数字 + 小标签 + 渐变作为无意义 Hero；
- 每段内容都放在白色圆角卡片中；
- emoji 作为功能图标；
- 用绿色代表所有正面状态；
- 规则总数、连续天数等虚荣指标占据首屏；
- hover scale 导致布局晃动；
- 在专注流程中保留底部全局导航；
- 中文界面使用只覆盖拉丁字符的展示字体；
- 没有真实验证数据却展示“有效”或里程碑。
